Four ways to fix the filter pane

Same page, same endpoint, same query params. What changes is where the filters live and what they look like once they're on. Every panel below is interactive — click the chips, open the pickers, remove a token.

What's actually wrong with it today

  1. 34 category chips in a six-row wall. No search, no counts, no order you'd guess. It's the biggest thing in the drawer and the hardest to use.
  2. Opening the filters pushes the table off screen. You lose sight of the thing you're filtering at the exact moment you're filtering it.
  3. Two ways to sort. "Sort by" and "Direction" dropdowns sit in the drawer while the table headers already sort on click, and the header arrow already shows the direction.
  4. Closed, the drawer hides what it's doing. A count on a button is not the same as being able to see — or drop — the one filter that's narrowing your list.
  5. The result line is the smallest text on the page. "2 810 results · −95 616 € / +99 309 €" is the most useful feedback here, set in grey 11px next to a button.
  6. The common queries take the most work. "This month", "over 100 €", "last week" are three or four interactions each, every time.
OPTION AFilter tokens in the barLinear · GitHub · Notion

Kill the drawer. A filter, once applied, becomes a token that lives in the bar — visible, individually removable, no layout shift. + Filter opens a small menu of facets; picking one opens its values. The result line moves up and gets a size that matches how much it's worth. Sorting belongs to the table headers and is deleted from here.

OPTION BOne query barGmail · Jira · Raycast

Everything collapses into a single field that understands a small language: market over:20 in:groceries after:1.7. Suggestions appear as you type, so the syntax is learned by using it rather than read. Built for the one expert who uses this app every day — you.

OPTION CPersistent facet railAirbnb · Amazon · any shop

Filters move out of the way of the table entirely, into a rail that's always open beside it. Every value carries the count it would give you and a bar for its share, so the filter list doubles as a summary of your spending. Categories are sorted by how much you actually use them, not alphabetically.

If you want a recommendation

D now, A next. D is an afternoon and clears every fault on the list, so the page stops feeling unfinished immediately. A is the one that actually changes the idea — filters you can see and drop without opening anything — and D's tokens are the same component, so building D isn't work you'd throw away.

C is the best of the four if you filter more than you scroll, and the counts are genuinely nice, but it wants a wide window and a faceted count query. B is the most fun and the fastest to use once learned — worth having as an addition to whichever you pick, not instead of it.
